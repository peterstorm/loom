# Next.js App Router Patterns

Checked against nextjs.org/docs and react.dev on 2026-11-12 (Next.js 16, React 19.2). Model knowledge of caching, request APIs and form hooks is usually one or two majors behind, so read the project's `package.json` and `next.config.*` before applying anything here. The installed version ships its own docs under `node_modules/next/dist/docs/`; when this file and those docs disagree, the installed docs win.

Module layout (`domain/`, `orchestrator/`, `infra/`, where Server Actions live) is defined in `${CLAUDE_PLUGIN_ROOT}/rules/typescript-patterns.md` → "Next.js App Router". It is not repeated here.

## What changed

| Version | Change |
|---|---|
| Next.js 15 | `params`, `searchParams`, `cookies()`, `headers()` and `draftMode()` are async. `fetch` and `GET` Route Handlers are no longer cached by default. Page segments are no longer reused from the client cache on `<Link>` navigation. React 19 is the minimum. |
| Next.js 16 | Synchronous access to the request APIs is removed. `middleware.ts` is deprecated in favour of `proxy.ts`. `revalidateTag` needs a second argument. `updateTag` and `refresh` are new. `cacheLife` and `cacheTag` lose the `unstable_` prefix. Cache Components (`cacheComponents: true`, the `'use cache'` directive) replace the experimental PPR and `dynamicIO` flags. Turbopack is the default bundler. `next lint` is removed. Every parallel-route slot needs a `default.js`. Node.js 20.9 and TypeScript 5.1 are the minimums. |
| React 19 | `useActionState` replaces `useFormState` (deprecated). `useFormStatus` and `useOptimistic` are available. `<form action={fn}>` accepts a function. |

## Server and Client Components

Components are Server Components unless the file starts with `'use client'`. Add the directive only where the component needs event handlers, state, effects or browser APIs, and push it as far down the tree as it will go. A Server Component can be `async` and await its data directly.

## Request APIs are async (Next.js 15; mandatory in 16)

```tsx
// app/blog/[slug]/page.tsx
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params
  const { q } = await props.searchParams
  return <Article slug={slug} highlight={q} />
}
```

`PageProps`, `LayoutProps` and `RouteContext` are global helpers generated by `next dev`, `next build` or `next typegen` (Next.js 15.5 and later). Without them, type the prop by hand: `{ params: Promise<{ slug: string }> }`. A Client Component unwraps the same promise with React's `use(props.params)`.

```ts
import { cookies, headers } from 'next/headers'

const cookieStore = await cookies()
const theme = cookieStore.get('theme')?.value
const userAgent = (await headers()).get('user-agent')
```

## Server Actions and forms (React 19)

A Server Action is reachable by a direct POST request, not only through the form that renders it. Authenticate and authorize inside every action; a check in the page or the layout does not protect it.

Return a discriminated union so the form can render each outcome. Log the caught error on the server and return a message written for the user; a raw `error.message` can carry SQL, file paths or secrets.

```ts
// lib/orchestrator/update-profile.ts
'use server'

import { updateTag } from 'next/cache'
import { z } from 'zod'
import { auth } from '@/lib/auth' // your auth solution

const Profile = z.object({
  name: z.string().min(1).max(100),
  email: z.string().email(),
})

export type ProfileErrors = Partial<Record<keyof z.infer<typeof Profile>, string[]>>

export type ProfileState =
  | { status: 'idle' }
  | { status: 'saved' }
  | { status: 'invalid'; fieldErrors: ProfileErrors }
  | { status: 'failed'; message: string }

// With useActionState the action receives the previous state first, then the FormData.
export async function updateProfile(_previous: ProfileState, formData: FormData): Promise<ProfileState> {
  const session = await auth()
  if (!session?.user) return { status: 'failed', message: 'Sign in to continue.' }

  const parsed = Profile.safeParse({ name: formData.get('name'), email: formData.get('email') })
  if (!parsed.success) {
    return { status: 'invalid', fieldErrors: z.flattenError(parsed.error).fieldErrors } // Zod 4
  }

  try {
    await db.user.update({ where: { id: session.user.id }, data: parsed.data })
  } catch (error) {
    console.error(error)
    return { status: 'failed', message: 'Could not save your profile. Try again.' }
  }

  updateTag(`user-${session.user.id}`) // Next.js 16; see "Invalidation" below
  return { status: 'saved' }
}
```

```tsx
// app/profile/profile-form.tsx
'use client'

import { useActionState } from 'react'
import { useFormStatus } from 'react-dom'
import { updateProfile, type ProfileErrors, type ProfileState } from '@/lib/orchestrator/update-profile'

const initialState: ProfileState = { status: 'idle' }

// useFormStatus reads the nearest parent <form>, so it must live in a child component.
function SubmitButton() {
  const { pending } = useFormStatus()
  return <button disabled={pending}>{pending ? 'Saving…' : 'Save'}</button>
}

export function ProfileForm() {
  const [state, formAction] = useActionState(updateProfile, initialState)
  const errors: ProfileErrors = state.status === 'invalid' ? state.fieldErrors : {}

  return (
    <form action={formAction}>
      <label htmlFor="name">Name</label>
      <input id="name" name="name" aria-invalid={!!errors.name} aria-describedby={errors.name ? 'name-error' : undefined} />
      {errors.name && <p id="name-error" role="alert">{errors.name[0]}</p>}
      <SubmitButton />
      {state.status === 'failed' && <p role="alert">{state.message}</p>}
    </form>
  )
}
```

- `useActionState(action, initialState)` returns `[state, dispatch, isPending]`. Pass `dispatch` to `<form action>`; React wraps the submission in a transition. Called from an event handler instead, `dispatch` must be wrapped in `startTransition`.
- `useOptimistic(value, reducer?)` returns `[optimisticValue, setOptimistic]`. Call the setter inside an action or `startTransition`; the optimistic value is shown while the action is pending and the real `value` replaces it when the action settles, including when it throws.
- `redirect()` throws a control-flow exception, so nothing after it runs. Invalidate first, redirect last, and keep it outside `try`/`catch`.

## Caching

Find out which model the project uses before writing a cache call: look for `cacheComponents` in `next.config.*`.

**In both models (Next.js 15 and later):** a plain `fetch` is not cached, a `GET` Route Handler is not cached, and navigating with `<Link>` does not reuse a page segment from the client cache.

**Cache Components (Next.js 16, `cacheComponents: true`).** Caching is opt-in per function or component with the `'use cache'` directive. Pair it with a lifetime and, where the data can change on demand, a tag.

```ts
import { cacheLife, cacheTag } from 'next/cache'

export async function getProducts() {
  'use cache'
  cacheLife('hours') // profiles: seconds, minutes, hours, days, weeks, max
  cacheTag('products')
  return db.query('SELECT * FROM products')
}
```

- Arguments and captured values become part of the cache key.
- A component that reads uncached data, or `cookies()`, `headers()`, `params` or `searchParams`, goes inside `<Suspense>`: the fallback ships in the prerendered shell and the content streams at request time. Without the boundary the dev overlay reports a blocking route.
- To cache something that depends on the request, read the runtime value outside and pass it into the cached function as an argument.
- Turning the flag on in an existing app is a migration, not a config tweak: it surfaces build errors for uncached data outside `<Suspense>`. Do not enable it as a side effect of another task.

**Previous model (no `cacheComponents`).** Opt in per request or per function:

```ts
await fetch(url, { cache: 'force-cache' })
await fetch(url, { next: { revalidate: 3600, tags: ['products'] } })
// Non-fetch work: unstable_cache(fn, keyParts, { tags, revalidate })
```

`export const dynamic = 'force-static'` opts a `GET` Route Handler back into caching.

**Invalidation (Next.js 16).**

| Call | Where | Effect |
|---|---|---|
| `updateTag('products')` | Server Actions only | Expires the tag immediately, so the user who made the change sees it |
| `revalidateTag('products', 'max')` | Server Actions and Route Handlers | Stale-while-revalidate: stale content is served while fresh content is generated. The one-argument form is deprecated and is a TypeScript error |
| `revalidatePath('/products')` | Server Actions and Route Handlers | Invalidates everything cached for the path; prefer a tag when one exists |
| `refresh()` from `next/cache` | Server Actions | Refreshes the client router; does not revalidate tagged data |

## Route Handlers and external data

Parse what crosses a boundary; never cast it. `await res.json() as User[]` asserts a shape nobody checked, and Loom's own linter refuses it (`no-wire-cast`). Bind the value as `unknown` and run it through a schema.

```ts
// app/api/users/[id]/route.ts
import type { NextRequest } from 'next/server'

export async function GET(_request: NextRequest, context: RouteContext<'/api/users/[id]'>) {
  const { id } = await context.params // a Promise since Next.js 15
  const user = await findUser(id)
  return user ? Response.json(user) : Response.json({ error: 'Not found' }, { status: 404 })
}
```

```ts
const response = await fetch('https://api.example.com/users')
if (!response.ok) return { ok: false, error: 'upstream-unavailable' } as const
const body: unknown = await response.json()
const parsed = z.array(User).safeParse(body)
return parsed.success ? ({ ok: true, value: parsed.data } as const) : ({ ok: false, error: 'unexpected-shape' } as const)
```

A Route Handler is a public endpoint: authenticate it and parse its request body the same way as a Server Action.

**Typed environment.** Parse `process.env` once, in a module the client bundle cannot import. Only variables prefixed `NEXT_PUBLIC_` are exposed to the browser; validate those in a separate module.

```ts
// lib/config/env.ts
import 'server-only'
import { z } from 'zod'

const Env = z.object({
  NODE_ENV: z.enum(['development', 'production', 'test']),
  DATABASE_URL: z.string().url(),
})

export const env = Env.parse(process.env) // throws at startup when a variable is missing
```

## Proxy (Next.js 16)

`middleware.ts` is deprecated. Rename the file to `proxy.ts` and the exported function to `proxy`. Proxy runs on the Node.js runtime and that cannot be configured; a project that needs the edge runtime keeps `middleware.ts` for now.

## Streaming and errors

- `loading.tsx` gives a route segment a loading state. `<Suspense>` gives a single component one; sibling boundaries load independently, so put each slow read in its own.
- `error.tsx` must be a Client Component. Its `error` prop is `unknown`: narrow it before reading `message`. In production an error thrown in a Server Component arrives with a generic message and a `digest` that matches the server log, so render your own copy instead of `error.message`. From Next.js 16.3 the recovery prop is `retry()`, which re-fetches and re-renders the segment; `reset()` re-renders without re-fetching.

## Accessibility

Distinctive design must be accessible.

### Keyboard navigation

```tsx
// Focus management for modals/dialogs
'use client'
import { useEffect, useRef, type KeyboardEvent, type ReactNode } from 'react'

type ModalProps = { isOpen: boolean; onClose: () => void; children: ReactNode }

function Modal({ isOpen, onClose, children }: ModalProps) {
  const modalRef = useRef<HTMLDivElement>(null)
  const previousFocus = useRef<HTMLElement | null>(null)

  useEffect(() => {
    if (!isOpen) return
    previousFocus.current = document.activeElement instanceof HTMLElement ? document.activeElement : null
    modalRef.current?.focus()
    return () => previousFocus.current?.focus() // restore focus on close
  }, [isOpen])

  const handleKeyDown = (event: KeyboardEvent) => {
    if (event.key === 'Escape') onClose()
  }

  if (!isOpen) return null
  return (
    <div ref={modalRef} role="dialog" aria-modal="true" tabIndex={-1} onKeyDown={handleKeyDown}>
      {children}
    </div>
  )
}
```

This sample shows the focus contract (move focus in, restore it on close, close on Escape); it does not trap focus. For dialogs, dropdowns and tabs in production use [Radix UI](https://radix-ui.com) or [React Aria](https://react-spectrum.adobe.com/react-aria/), which handle keyboard, focus and ARIA correctly.

### ARIA patterns

```tsx
// Live region for dynamic content
<div aria-live="polite" aria-atomic="true" className="sr-only">
  {notification}
</div>

// Form error association
<label htmlFor="email">Email</label>
<input id="email" aria-invalid={!!error} aria-describedby={error ? 'email-error' : undefined} />
{error && <p id="email-error" role="alert">{error}</p>}

// Skip link for keyboard users
<a href="#main-content" className="sr-only focus:not-sr-only">
  Skip to main content
</a>
```

### Contrast and motion

- Body text needs a contrast ratio of at least 4.5:1 against its background, large text 3:1. Measure muted and placeholder text too; that is where palettes fail.
- Every animation needs a reduced-motion path. The global rule is in `animation-recipes.md`.
