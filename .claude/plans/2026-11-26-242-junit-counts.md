# #242 — JUnit suite counts follow the testcases the runner wrote

## Problem

Surefire + jqwik writes a suite attribute `tests=` that counts containers/test
methods, not the `<testcase>` invocations jqwik generated. The parser requires
the attribute to equal the sum of its testcase children, so a real mixed
jqwik/Jupiter report (`tests="7"`, 12 testcases) is refused as
`malformed-counts`. The run is untrusted, and I6 green can never be shown.

Cause 1 of #242 (simple JVM class names and `$Nested`) already shipped in
#243. This is the remaining half.

## Decision

Within one JUnit suite that lists `<testcase>` elements, the elements are the
executed facts: total, failed and skipped derive from them, and a disagreeing
`tests` attribute is metadata. Summary-only suites keep today's strict
attribute accounting, so a summary-only report must still reconcile. A suite
whose `failures + errors` attribute claims more failures than its testcase
children show stays refused: a claimed failure with no element is not
evidence that the run passed.

The node dialect (`testsuites` with direct testcase children) is unchanged.

## Changes

1. `engine/src/core/structured-test-report.ts`
   - `parseTraditionalJunit`: return the observed testcase counts when the
     subtree lists testcases; keep the current attribute path when it does not.
   - Refuse a claimed failure count above the observed failing testcases.
2. Tests
   - Mixed Surefire (`tests="7"`, 12 cases) parses as 12 executed, per-file
     recorded.
   - Nested suite under an undercounted outer suite parses from its cases.
   - A claimed failure with no failing testcase stays `malformed-counts`.
   - Update the two tests that encoded the old "attributes must agree" rule.
3. `docs/adr/ADR-0103-a-junit-suite-is-counted-from-its-testcases.md`: a new ADR amending ADR-0100.
   The "no real runner writes this" premise is false for Surefire + jqwik. ADR-0100's Status gains
   the relation; its decision stays untouched, per the ADR norm. Update the ADR index.
4. `docs/verification.md`: state the operator-facing rule beside the report
   attribution paragraph.
