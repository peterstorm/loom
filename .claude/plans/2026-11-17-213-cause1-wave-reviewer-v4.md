# #213 Cause 1: Wave reviewer payloads carry no packet identity (reviewer protocol v4)

- Issue: peterstorm/loom#213, Cause 1. Worktree: `../loom-review-identity`, branch `fix/reviewer-packet-identity` from origin/main (9ee88a95).
- Open PR not to collide with: #212 (active-Wave plan edits and coupled file sets, another session).
- Decision (operator, 2026-11-17): new payload version, not just restart scoping.
- Scope: part (a) only. Restart carry-over, part (b), is a separate PR with its own ADR.

## Problem

ADR-0009 requires Wave reviewers to echo the exact `packetId` (a 64-hex sha256) and `generation`, and attempt 2 is final. In a real run a reviewer mistyped the hash on its final attempt, the slot was exhausted, and `orchestration restart` reissued all 35 requests. The engine already binds both values: the issued request names the slot and the context packet digest.

## Decided design (verify against the code and adjust)

- **Layout and decoder.** Keep the outer layout at `schemaVersion: 2` for registration and packet; the **descriptor** selects the decoder.
- **Contract leaf: `engine/src/core/reviewer-contract.ts`.** Keep the zod schemas here.
  - Schema: `waveReviewerPayloadV4Schema = strictObject({schemaVersion: literal(4), kind: literal("wave-review"), prior_findings, findings})`, reusing the existing prior_findings and draft schemas.
  - Constants: `WAVE_REVIEWER_PAYLOAD_SCHEMA_V4` (generated bytes, like v2) and `WAVE_REVIEWER_PROTOCOL_V4 = {protocol:"loom-reviewer", version:4, rubricVersion:1, schemaDigest, rubricDigest}`. Version 4 so it never collides with the standalone v3 descriptor from ADR-0010.
  - Types: `ReviewerProtocolDescriptor` becomes a union of v2 and v4.
  - Descriptor parsing becomes program-aware: v2 for anyone, v4 only for `wave-gate`. The standalone paths stay v2-only: `standalone.ts`, `standalone-review*.ts` and `remediation-machine.ts` (~631).
  - Also add v4 fixed packet sections and a parsed Wave v4 example (ADR-0073).
- **`reviewer-protocol.ts`:**
  - `parseWaveReviewerPayloadV4`;
  - a "wave v4" arm in `schemaRefusal`, with an envelope hint;
  - a Wave v4 section in `renderReviewerWireContract`.
- **`context-packets.ts`:** `reviewerPacket` and `buildReviewerContextPacket` take the descriptor and choose fixed sections by its version; parsing reads it from `record.reviewerProtocol`.
- **`wave-review-authority.ts`:** pass `registration.reviewerProtocol` into the packet builder.
- **`programs/wave-gate-start.ts` (~80):** new registrations use `WAVE_REVIEWER_PROTOCOL_V4`.
- **`programs/wave-gate-replacement.ts` (~123, ~225):** restart and orphan recovery **inherit `previous.reviewerProtocol`**, so a run never changes protocol.
  - *Superseded during implementation:* replacements always issue v4 (ADR-0084). A replacement reissues every request, so no reviewer straddles two protocols and inheriting the predecessor's descriptor buys nothing.
- **`review-output.ts`:**
  - `parseIssuedReviewerProtocol` uses the program-aware parse.
  - `currentPriorRosterIsRepresentable` sizes the roster per version.
  - `parseCurrentReviewerEvidence` branches on the descriptor version. v2 stays byte-for-byte as today. v4 runs the v4 parser, checks kind, out-of-scope files (keep the named message) and ordered priors, then sets `bound` from `subject.packetId/generation`.
- **Emission:**
  - `reviewer-emission-route.ts` `projectRegisteredReviewerProtocol` accepts v4 for wave-gate.
  - `issued-emission-capability.ts` adds a "v4" claim, selected by descriptor version.
  - `emission-tool.ts` adds a reviewer-payload cell v4.
  - Check whether route qualification (ADR-0012, probes) enumerates cells.
- **Persisted descriptor checks** accept the union: `state-file-wire.ts` (~1687), `findings.ts` (~895), `findings-shape.ts` (~155, ~180).
- **Wording:** `spawn-task-text.ts` (~127) and the retry text (`reviewer-retry.ts`, `programs/wave-review-retries.ts`). v4 says "do not copy packetId/generation"; v2 wording stays unchanged.
  - *Superseded during implementation:* the retry-wording changes were unnecessary. The retry tail is protocol-agnostic, so `reviewer-retry.ts` and `programs/wave-review-retries.ts` are unchanged.
- **Stamped files:** regenerate with `bun scripts/stamp-wire-contract.ts`. That rewrites `references/reviewer-wire/wire-contract.md` and the 7 reviewer agents' stamped regions. The shared text must serve live v2 runs and v4 runs alike: "the packet's reviewer-payload-schema governs; the task states whether packetId/generation are required". Do not touch the archived `references/reviewer-protocol-v1*`.
- **Docs:**
  - A new ADR (next free number), "Wave reviewer payloads carry no packet identity; the issued subject binds it". It partly supersedes ADR-0009's exact packet/generation join; priors stay required and attempt 2 stays final.
  - A status note in ADR-0009.
  - Updates to `docs/adr/README.md` and `docs/contexts/review/CONTEXT.md`, plus every doc that tells Wave reviewers to copy packetId.

## Tests (red first)

- **New:**
  - v4 admits a payload with no packetId/generation and binds both from the subject;
  - a v4 payload that includes packetId is refused (strict);
  - v4 still requires the full ordered prior roster;
  - v4 still names out-of-scope files.
- **Regression:**
  - a v2-registered Wave run still requires packetId/generation and refuses a v4 payload;
  - standalone registrations refuse the v4 descriptor;
  - restart and orphan replacement inherit the predecessor's descriptor.
    - *Superseded during implementation:* the regression test asserts that a v2 predecessor yields a v4 replacement (ADR-0084); see the `wave-gate-replacement.ts` note above.
